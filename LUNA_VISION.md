# Luna Vision Document
The philosophy, pillars, and product direction for everything we build.

---

## The Core Premise

Luna is not a period tracker. Period trackers are forms you fill out so a chart can tell you what you already know. Luna is something entirely different.

Luna is a living companion that understands you before you have to explain yourself.

During the hardest days of a cycle - the cramps, the fog, the days when you don't even want to think - the last thing someone needs is an app demanding input. They need something that already knows. That already understands the biology, the patterns, the personal history of this person. And responds accordingly.

Luna's job is to be so tuned in to the person it serves that it feels less like software and more like something that just gets you.

---

## The Non-Negotiables

### 1. Context is always known. Not asked.
Luna should never require the user to tell it what it already knows or can infer. The current phase, the expected physical state, the hormonal context, the historical patterns - these are always loaded, always in the background, always informing every surface of the app.

### 2. Data collection is a gift, not a requirement.
When a user logs, they are giving Luna a gift. Not providing input for a system. Logging should feel effortless - ideally a single tap. What users don't tell Luna, Luna doesn't invent. ZERO defaults silently recorded.

### 3. Intelligence is a pillar, not a feature.
Luna's intelligence - the pattern recognition, the longitudinal learning, the predictions - must be invisible. It does not announce itself. It does not say 'based on our AI analysis.' It just IS.

### 4. Period detection is automatic.
'Did your period start today?' should never live as a static always-visible button. Luna notices when symptoms like cramps and flow are logged. It infers. When it thinks today might be Day 1, it asks - once, gently, in context. If confirmed, anchor updates.

### 5. Personalization deepens with time, silently.
Months of data should make Luna feel like a companion who's been with you - not like a dashboard that has more bars in its charts.

### 6. The UI should feel like a place, not a tool.
Every screen Luna shows should feel intentional, considered, and warm. Nothing lazy. Nothing generic.

---

## The Five Pillars

1. Biological Intelligence - The app knows the phase, the hormones, the expected state. Always.
2. Pattern Memory - Over time, Luna builds a personal map of this specific person's cycle.
3. Effortless Capture - Logging should take seconds. One tap is enough.
4. Personal Voice - Every AI response is written for this person, right now. Never generic.
5. Invisible Smartness - Intelligence shows in outcomes, not UI labels. Never boast. Just be smart.

---

## What Luna is NOT
- Not a calendar with health features
- Not a chatbot wrapper around a tracker
- Not a form. Ever.
- Not an app that requires input to give output
- Not generic. Not a template. Not lazy.

---

## Implementation Mandate

Every feature, every screen, every line of UI copy must pass this filter:

Does this make Luna feel more like a companion who already knows this person -
or does it make Luna feel like an app asking for input?

If it is the latter, redesign it until it is the former.

When in doubt: less on the surface, more underneath.
